# PR 현황 보고서와 분류 라벨 (2026-11-06)

범위 (소유자 결정): PR 현황 보고서 하나를 주기적으로 갱신하고 관리 라벨을 붙인다. PR 을 자동으로 닫거나 병합하지 않는다.
워크플로 `.github/workflows/claude-pr-triage.yml`, 스크립트 `scripts/pr_triage.py`, 시험 `tests/test_pr_triage.py`.

## 흐름

| job | AI | 권한 (워크플로 토큰) | 하는 일 |
| --- | --- | --- | --- |
| collect | 없음 | contents·pull-requests·issues·checks·statuses 읽기 | 열린 PR 의 head SHA, CI, Draft, 충돌, 리뷰 승인을 모아 스냅샷과 digest 를 만든다. 보고서 이슈의 digest 와 비교해 "사실 변화", 현재 관리 라벨과 비교해 "라벨 어긋남" 을 따로 낸다 |
| summarize | Claude (구독, 읽기 전용) | contents 읽기, id-token | 사실이 바뀌었고 열린 PR 이 있을 때만. 스냅샷 파일만 읽고 우선순위 (높음·보통·낮음) 와 다음 조치 한 문장을 구조화 출력으로 낸다. `--tools "Read"` 로 내장 도구를 Read 하나로 줄이고 `mcp__*` 를 거부해 MCP 도구도 뺀다. 5 턴 |
| publish | 없음 | issues·pull-requests 쓰기 (+ 읽기) | 다시 수집해 스냅샷과 다르면 쓰지 않는다. Claude 출력을 검증하고, 관리 라벨과 봇 소유 보고서 이슈 하나만 갱신한다 |

실행: 2 시간마다 (`cron: "17 */2 * * *"`, KST 01:17, 03:17, …, 23:17) 와 수동 (`workflow_dispatch`).
사실이 바뀌지 않은 회차는 collect job 하나 (AI 없음) 로 끝나 LLM 호출을 생략한다. 다만 주기가 짧으면 더 자주 바뀐 상태를 포착하므로 총 호출은 늘 수 있다. `concurrency` 로 한 번에 하나, job 시간 제한 5·15·5 분.
Claude job 은 다른 Claude 워크플로와 같은 방식 (구독 토큰 확인, bubblewrap, `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, App 토큰 읽기 전용) 이다.

## 라벨 (결정적)

관리 라벨은 `pr-triage/` 접두사만이다. 다른 라벨 (Dependabot 의 `dependencies` 등) 은 읽기만 하고 바꾸지 않는다.

| 라벨 | 조건 |
| --- | --- |
| `pr-triage/needs-review` | 리뷰 결정이 `REVIEW_REQUIRED` |
| `pr-triage/changes-requested` | `CHANGES_REQUESTED` |
| `pr-triage/ci-failing` | 실패한 검사가 하나라도 있음 (FAILURE, TIMED_OUT, STARTUP_FAILURE, ACTION_REQUIRED) |
| `pr-triage/blocked` | 나머지 확인 (Draft 아님, 충돌 없음, CI 통과, 리뷰 승인) 은 통과했지만 병합 상태가 BLOCKED·BEHIND·UNSTABLE 등 |
| `pr-triage/ci-pending` | 진행 중인 검사가 있음 |
| `pr-triage/conflict` | `mergeable = CONFLICTING` |
| `pr-triage/draft` | Draft |
| `pr-triage/unknown` | head, Draft, mergeable, 리뷰 결정, 병합 상태가 없거나 UNKNOWN. 필수 검사 `Lean build and audits` 가 없거나 SUCCESS 가 아님 (SKIPPED·NEUTRAL·취소 포함) |
| `pr-triage/ready` | 위가 모두 확인되고, Draft 아님, 충돌 없음, CI 통과, 리뷰 `APPROVED`, 병합 상태 `CLEAN` 또는 `HAS_HOOKS` |

CI 가 녹색이어도 리뷰 승인이 없으면 `ready` 가 아니다. 필수 검사는 실제 SUCCESS 여야 하고, 비필수 검사 (PR 에서 건너뛰는
`Build blueprint and deploy` 등) 는 SKIPPED·NEUTRAL 도 통과로 본다. 판단할 수 없는 사실은 `unknown` 이다. 분류는 빈 집합이 되지 않는다.

## 중복 억제와 낡은 상태

- 보고서 이슈 본문에 사실의 digest 를 `<!-- pr-triage-digest: … -->` 로 남긴다. digest 에는 시각과 현재 관리 라벨이 들어가지 않는다.
  그래서 첫 게시가 라벨을 바꿔도 다음 실행은 "변화 없음" 이고 LLM 을 부르지 않는다.
- 사실이 같고 관리 라벨만 사람이 지우거나 바꾸면 LLM 호출과 본문 재작성 없이 라벨만 복구한다.
- 게시 직전에 다시 모은 사실이 스냅샷과 다르면 아무것도 쓰지 않고 경고를 남긴다. 다음 실행이 다시 모은다.
- 보고서 이슈는 봇 (`github-actions`) 이 만들고 `pr-triage/report` 라벨, 고정 제목 "PR 현황 보고서 (자동)", 본문의 고정 표식
  `<!-- pr-triage-report:v1 -->` 를 모두 가진 열린 이슈 하나다. 사람이 만든 이슈나 표식·제목이 다른 이슈는 쓰지 않는다.
  그런 이슈가 여럿이면 임의로 고르지 않고 실패한다.
- 열린 PR 은 100 개, 보고서 라벨 이슈는 20 개가 상한이다. 상한 + 1 로 조회해 넘치면 잘린 목록을 전체라고 게시하지 않고 실패한다.
- 라벨 이름의 `/` 는 REST 경로에서 `%2F` 로 인코딩한다 (`label_exists`, 라벨 제거).

## Claude 출력 검증

digest 가 스냅샷과 같고, 스냅샷의 모든 PR 이 정확히 한 번 나오고, 우선순위가 허용값이고, 다음 조치가 비지 않아야 한다.
다음 조치는 한 줄로 줄이고 160 자로 자르며 표 구분자·HTML·멘션·digest 표식을 무력화한다. 라벨은 Claude 가 정하지 않는다.

## 재사용 workflow 이관 제안 (2026-11-10)

이관 PR은 `Maokami/continuous-ai-kit`의 `pr-triage.yml`을 전체 SHA로 고정한다.
기본 설정은 `.github/continuous-ai/pr-triage.json`에 명시하며 기존 관리 라벨·보고서 마커·facts digest를
유지한다. `scripts/pr_triage.py`와 25개 호환 시험은 롤백용으로 남긴다. 기존 inline shell 시험은 caller
계약 검사로 바꾸고 stale exit 3 처리의 실행 시험은 kit에서 계속한다.

kit의 AI job은 contents 읽기 권한만 받으며 GitHub token을 명시해 OIDC를 요청하지 않는다.
restricted mode와 Read 하나, strict 빈 MCP를 사용한다. 예전 bubblewrap 설정과 같은 OS sandbox라고
주장하지 않으며, 코드 실행 도구를 제공하지 않는다. artifact는 run_attempt별로 보관한다.

소유자의 일반 브랜치에서 draft PR로 검토한다. 승인 1건·사람 머지 정책은 바꾸지 않는다.
머지 후 사람이 첫 수동 실행을 확인하고 문제가 있으면 caller를 이관 전 버전으로 되돌린다.
헌터·수학 파일·다른 Claude workflow는 이 이관 범위에 포함하지 않는다.
