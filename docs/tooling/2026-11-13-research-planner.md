# 일일 연구 과제 제안과 실행 큐

사용자가 승인한 범위: PR #16까지의 연구 현황 갱신, 초기 과제 세 개, 일일 제안 워크플로 하나.
기존 Claude 구독 인증, 사냥꾼의 소유자·본문 편집자 확인, draft PR, 승인 1건과 필수 CI를 유지한다.

## 실행과 권한

`.github/workflows/claude-research-planner.yml`을 매일 09:07 KST 및 수동으로 실행한다.
먼저 AI 없이 현재 main, 연구 이슈/실패 댓글, 문헌 보고, 연구 PR을 수집한다.
이전 보고서와 입력 해시가 같거나 열린 연구 PR이 두 개 이상이면 AI·게시를 건너뛴다.
모든 이슈 100개, PR 200개, 연구 이슈당 댓글 100개 미만, 입력 120 KB가 상한이다.
잘린 목록이나 API 오류는 성공으로 취급하지 않는다.

AI는 읽기 전용이며 15턴·12분 한도로 후보 최대 3개를 JSON으로 낸다.
열린 `research-audit` 하나를 우선 조사하고, 실제 읽은 1차 출처와 확인하지 못한 범위를 기록한다.
출력은 목표 진술·허용 가정·의존성·줄일 병목·완료 기준·중단/재시도 조건을 갖는다.
후보가 없다는 결과도 허용한다. 구조 검사는 내용의 참이나 원문 대조의 정확성을 보증하지 않는다.

별도 AI 없는 게시 job이 입력을 다시 모으고, main/이슈/댓글/연구 PR/보고서 대상이 달라졌으면 쓰지 않는다 (종료 3).
봇이 만들고 고정 마커를 가진 `research-plan/report` 이슈 하나만 갱신한다.
게시 job에는 Claude 인증을 주지 않고, AI job에는 issues 쓰기를 주지 않는다.
Action과 artifact 도구는 전체 SHA로 고정한다. artifact는 공개 연구 입력과 구조화 출력 두 파일뿐이다.

## 후보를 실행 과제로 옮기기

보고서는 실행 큐가 아니다. 소유자가 후보의 진술·가정·중복·연구 기여를 검토하고 이슈를 작성한다.
형식화 과제에는 `lemma-hunt`, 문헌 대조에는 `research-audit` 라벨을 쓴다.
봇이 생성한 후보를 라벨 하나로 자동 승인하거나 기존 소유자 검사를 완화하지 않는다.
초기 세 과제의 승인된 계약은 `docs/research-tasks/`에 보관하며, 게시할 이슈 본문은 해당 파일 그대로 쓴다.
문헌 대조는 제안자의 보고서로 조사하되 완료 판정은 별도 근거 검토 뒤에 한다.

사냥꾼은 기존 매일 09:37 KST, 최대 열린 연구 PR 두 개로 유지한다.
2026-11-13부터 같은 본문은 main SHA가 바뀌어도 자동 재시도하지 않는다.
재시도에는 소유자의 본문 전략 수정 또는 명시적 수동 지시가 필요하다. 시작 기록은 실행 SHA와 함께 계속 보존한다.
